# RedForge

> Autonomous smart-contract **exploit & formal-verification** engine. Point it at a Solidity repo; it finds vulnerabilities, **proves** them with harness-checked exploits, patches them, and **formally verifies** the fix.

A multi-agent system that audits Solidity repositories end to end: it maps the
code, forms attack hypotheses, **proves** vulnerabilities with harness-checked
oracles, patches them with minimal diffs, and **formally verifies** the fix with
symbolic execution — then opens a PR with the patch, gas diff, SARIF and proof.

What separates this from "an LLM wired to Slither":

- **Oracle-gated proofs.** The harness — not the model — decides whether an
  exploit worked (attacker balance up, invariant broken, unauthorized state
  change, funds locked). False positives are structurally hard.
- **Formal verification.** The fix is proved with [Halmos](https://github.com/a16z/halmos)
  symbolic testing, not just re-run tests.
- **Benchmarked.** Scored against SmartBugs Curated, Damn Vulnerable DeFi and
  Ethernaut, with a published results table vs a Slither baseline.
- **Hardened sandbox.** All untrusted code runs in Docker with no network,
  resource caps, dropped capabilities, non-root, read-only rootfs.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env            # add your Anthropic key

docker build -t redforge-sandbox:latest -f docker/sandbox.Dockerfile .
redforge sandbox-check              # verifies the sandbox + that network is off

redforge scan https://github.com/OWNER/REPO   # Phase 1: clone + detect + Slither
```

## Status

Phase 1 (foundation) is in place: config, schemas, hardened sandbox, repo
cloner + toolchain detector, Slither integration, oracle checker, benchmark
harness, CLI, tests. Phases 2–8 (LangGraph graph, PoC loop, remediation,
verification, memory, product layer) are specified in **[CURSOR.md](./CURSOR.md)**.

## Layout

```
src/redforge/
  config.py          settings (env-driven)
  schemas.py         typed contracts + shared AuditState
  sandbox/           hardened Docker runner
  repo/              cloner + project detector
  static_analysis/   Slither runner -> Finding[]
  foundry/           forge test wrapper (sandboxed)
  oracles/           success oracles (anti-cheat)
  eval/              benchmark datasets + metrics harness
  cli.py             redforge entrypoint
docker/sandbox.Dockerfile
tests/
```

## Safety

Proof-of-concept exploits are generated by the agent **at runtime**, only
against benchmark or user-submitted contracts, and only inside the sandbox.
The repo ships no working exploits. See the threat model in
`src/redforge/sandbox/runner.py` and CURSOR.md § Safety.
